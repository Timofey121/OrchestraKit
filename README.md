# OrchestraKit

OrchestraKit организует работу с кодом в Codex: помогает разделить большую
задачу между исполнителями, выбрать модели и проверить результат. Небольшие
задачи главный агент выполняет в текущем чате. В локальной панели можно
переключаться между проектами, смотреть чаты и настраивать модели.

## Установка через чат

Откройте свой проект в Codex и отправьте этот промпт:

```text
Установи OrchestraKit и подключи его к текущему проекту этого чата:
https://github.com/Timofey121/OrchestraKit

Склонируй набор в отдельную папку для инструментов и прочитай
инструкцию docs/getting-started.md. Проверь Python 3.11+ и окружение Codex.
Установи пользовательский скилл и хуки через setup, затем подключи
текущий проект через init. Если он уже подключён, используй sync.
Сохрани существующие настройки, инструкции и мои изменения в проекте.

Выполни doctor для проекта и setup --check. На macOS включи автозапуск
панели через ui-autostart install; на других ОС запусти панель вручную.
Дай ссылку на неё и покажи, где выбирать модели и внешних провайдеров.
Если Codex требует подтверждения хуков, объясни, что мне подтвердить.
В конце сообщи результат проверки и как начать работу в новом чате.
```

Агент выполнит установку в пределах своих разрешений. Доверие к хукам
подтвердите в `/hooks`, затем откройте новый чат проекта. Для нативных
исполнителей нужен Codex CLI; на Windows используйте WSL.

[Репозиторий](https://github.com/Timofey121/OrchestraKit) ·
[Ручная установка и решение проблем](docs/getting-started.md)

## Как пользоваться

Поставьте задачу обычными словами, например:

> Добавь экспорт отчёта в CSV. Сохрани текущий формат данных,
> запусти тесты и покажи результат. Ничего не коммить.

Адрес панели: `http://127.0.0.1:8731`. Выберите проект, затем чат или задачу.
На macOS можно один раз включить фоновый запуск:

```bash
python3 ~/.agents/skills/orchestra/scripts/orchestra.py ui-autostart install
```

Панель запускается при входе в macOS и перезапускается после сбоя, даже если
закрыть терминал или чат. Для проверки используйте `ui-autostart status`,
для отключения — `ui-autostart uninstall`. На других ОС запустите её командой `ui`.

## Возможности

- Отдельные роли для исследования, реализации, тестирования и ревью.
- [Готовые сценарии](docs/native-workflow.md#готовые-сценарии) для исправления багов,
  новых функций и рефакторинга, с короткими инструкциями и прежними проверками.
- Выбор профиля по сложности и риску; переход к более сильной модели при
  повторных ошибках, с ограничением числа попыток.
- Привязка проверок и ревью к версии файлов по настройке проекта.
- История задач, очередь с зависимостями, отмена запусков и отдельные рабочие копии.
- Проекты, чаты, настройки моделей и доступные счётчики токенов в одной панели.
- [Сравнение вариантов процесса и краткая диагностика](docs/workflow-comparison.md)
  с проверкой качества и учётом всех попыток.
- [Память принятых решений и карта кода](docs/memory-navigation.md), с проверкой
  актуальности файлов и передачей отвергнутых подходов между попытками.
- [Разовая консультация сильной модели](docs/consultation.md) для узкого вопроса
  при тупике, с отдельным учётом расхода.
- [Цикл выполнения с ревью и исправлениями](docs/native-workflow.md), общими
  лимитами и необязательным повторным использованием актуальных проверок.

В разделе «Модели» можно настроить исполнителей и подключить внешний сервис.
Он должен поддерживать **Responses API и нужные инструменты Codex**. Ключи
хранятся отдельно от кода: в окружении или macOS Keychain. Модель главного
чата по-прежнему выбирается в Codex. Экономию оценивают по реальным запускам;
фиксированного процента OrchestraKit не обещает.
