# Консультация при тупике

`consult` задаёт сильной модели один узкий вопрос. Например: какую гипотезу
проверить, когда предыдущие попытки не устранили ошибку. Исполнитель получает
совет, а главный агент решает, что делать дальше.

Это необязательная команда. Она не вызывается при каждой ошибке, не запускает
предложенные проверки и не заменяет тесты или независимое ревью.

## Запрос

Создайте `consult.json`:

```json
{
  "question": "Какая гипотеза объясняет повторяющийся сбой разбора ответа?",
  "goal": "Исправить разбор ответа, сохранив публичный формат",
  "constraints": ["Не ослаблять тесты", "Не менять внешний формат"],
  "acceptance": ["Исходные сценарии проходят"],
  "files": ["src/client.py", "tests/test_client.py"],
  "evidence_refs": [],
  "rejected_approaches": [{
    "text": "Повторить запрос без изменения разбора",
    "reason": "Ошибка воспроизводится",
    "artifact_ref": ".orchestra/checks/failed-attempt.log"
  }]
}
```

Артефакт попытки должен существовать в `.orchestra/checks` или
`.orchestra/executions`. Если есть сертификаты успешных проверок этих файлов,
добавьте их в `evidence_refs`: команда проверит их актуальность. При неуспешных
проверках список может оставаться пустым. Версия исходников фиксируется в любом
случае; изменение контекста во время запроса делает совет непригодным.

```bash
./bin/orchestra consult "<проект>" --input consult.json --dry-run
./bin/orchestra consult "<проект>" --input consult.json
```

Первый вызов проверяет запрос и маршрут без обращения к модели. Второй делает
один запрос через Codex CLI. Профиль `strong` берётся из настроек проекта;
роль исследователя должна использовать песочницу `read-only`. Если маршрут
не подходит, команда возвращает работу главному агенту.
Внешний провайдер должен объявлять поддержку инструментов `function`;
доступность его реальной модели проверяется отдельно.

Ответ содержит `hypotheses` и `next_checks`, фактические доступные счётчики
токенов и ссылки на журнал запуска. Статус `advisory` означает «совет получен».
Он не подтверждает исправление кода и не создаёт сертификат успешной проверки.
Ошибочный ответ, отмена или недоступный инструмент возвращаются главному агенту
без автоматического повторного запроса.

## Когда использовать

Сначала сузьте вопрос, приложите нужные пути и объясните, какие подходы уже
проверены. Не передавайте всю историю чата. Консультация имеет собственный расход;
сравнивайте её вместе с последующей работой исполнителя и проверками. Уменьшение
числа эскалаций само по себе не доказывает экономию.

## Остальные эксперименты

На проверенном хосте Codex CLI умеет продолжать сеанс по точному UUID.
Проба сохранила контекст, но модель при продолжении сменилась без явного
закрепления. Команда `exec resume` также не предоставляет отдельные флаги
`--sandbox` и `--cd`. Наследование этих условий не проверено независимо.
Поэтому Orchestra продолжает использовать новые `--ephemeral`-сеансы:
автоматическое продолжение пока не включено.

Перед включением нужны проверка модели, проекта, окружения, разрешений,
изменившихся файлов и полный учёт попыток. Ревьюер должен оставаться независимым.
Возможность CLI продолжить разговор не доказывает безопасность повторного
использования старого контекста.

Загрузкой описаний MCP в основном чате управляет хост Codex. Orchestra не
обещает уменьшить его системный контекст. Для короткого вопроса исследователю
доступен [локальный протокол через главного агента](questions.md).
Согласование нескольких моделей не включено: для него нужны отдельные
проверки пользы и общего расхода.
