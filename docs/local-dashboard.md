# Локальная панель Orchestra

Панель показывает проекты, чаты Codex, сохранённые задачи, запуски исполнителей,
повторные попытки, проверки и доступные счётчики токенов. Она читает локальные
файлы и обновляет экран каждые три секунды. Для обновления не вызываются модели.

Из папки OrchestraKit запустите:

```bash
bin/orchestra ui .
```

Команда откроет браузер по адресу `http://127.0.0.1:8731`. Сервер работает, пока
работает команда; `Ctrl+C` завершает его. Чтобы выбрать другой порт или открыть
браузер самостоятельно:

```bash
bin/orchestra ui . --port 8732 --no-browser
```

Через установленный скилл панель доступна из другой рабочей папки:

```bash
python3 ~/.agents/skills/orchestra/scripts/orchestra.py ui /путь/к/проекту
```

Можно передать несколько папок:

```bash
bin/orchestra ui /путь/к/первому /путь/ко/второму
```

Панель также находит зарегистрированные локальные проекты Codex, в том числе
проекты без чатов и без Orchestra. Название берётся из Codex: например, проект
`replika` может находиться в папке `AbitCall`. При отсутствии регистрации
используется название из настроек Orchestra или имя папки. Чаты относятся к
проектам по сохранённой связи Codex; путь рабочей папки служит запасным вариантом.
Для просмотра только переданных папок используйте `--no-codex`. Для отдельной
установки Codex можно передать `--codex-home /путь/к/codex`.

## Что видно на экране

- «Обзор»: сохранённые задачи, текущие сообщения чатов, модели проекта и история.
- «Чаты»: название, проект, модель и последнее доступное событие каждого чата.
- «Исполнители»: попытки, смена модели, причины остановки и очередь зависимостей.
- «Расход токенов»: доступные счётчики исполнителей, включая неудачные попытки.
- «Модели и подключения»: профили исполнителей и внешние провайдеры выбранного проекта.

Откройте карточку проекта: появятся его чаты, задачи и история исполнителей.
Откройте чат: справа будет его работа, слева — соседние чаты того же проекта.
Ссылка «Открыть в Codex» ведёт в сам чат. Выбранный проект и чат сохраняются
в адресе страницы; обновление страницы и кнопка «Назад» сохраняют этот маршрут.
Верхнее меню позволяет перейти в другой проект. Разделы подписаны в левой панели;
на узком экране она превращается в нижнюю прокручиваемую навигацию.

На карточке проекта виден последний сообщённый шаг активного чата. Кнопка
«Открыть этот чат» ведёт прямо к нему. Описание берётся из содержательной реплики
ассистента; общий маркер инструмента используется, если такой реплики нет.
Задачи со статусом «В работе» показаны отдельно: запись не подтверждает,
что процесс всё ещё работает. При неизвестном состоянии чат получает статус «Состояние неизвестно».

Поиск работает по названию, модели и ID; `/` переводит фокус в поиск,
`Esc` закрывает подробности. Кнопка паузы останавливает только обновление экрана.
Работа оркестра продолжается. Фильтры чатов отделяют текущие ответы от архива.

## Подключение моделей

В разделе «Модели и подключения» выберите профиль, провайдера и модель.
Несохранённые настройки защищены от случайного перехода в другой раздел или
проект. Перед перечитыванием форма тоже попросит подтвердить сброс изменений.
Список содержит модели из настроек проекта и импортированных локальных каталогов.
Через «Ввести другой ID модели» можно указать идентификатор вручную.

В блоке «Кто использует модель» назначьте профиль ролям. Адаптивный выбор
позволяет повысить профиль по сложности и риску. Выключите его для фиксированного
профиля роли. Порядок усиления меняется кнопками «Выше» и «Ниже».

При добавлении провайдера можно вставить JSON-каталог с массивом `models`.
Нужен полный каталог Codex: каждая модель содержит `slug`, `display_name`,
`supported_reasoning_levels`, параметры инструментов и остальные метаданные из документации
провайдера. Указанные в каталоге уровни усилия проверяются при сохранении.
Каталог сохраняется в `.orchestra/providers`; изменение файла делает старую
форму неактуальной. Каталог описывает модели, но не подтверждает доступ к API.

Для локального Responses-сервера без авторизации снимите «API требует ключ».
Для внешнего провайдера Orchestra использует нативный `execute`: ключ
передаётся в окружение дочернего процесса. При недоступном запускателе
оркестр сообщает об ограничении, а не подменяет провайдера.

Настройки моделей принадлежат проекту и применяются к новым запускам его
исполнителей во всех чатах. Руководитель остаётся на модели, выбранной в Codex.
У уже запущенного исполнителя модель не меняется. Ручное делегирование через
инструменты Codex также зависит от доступных моделей и инструкций этого чата.

Можно добавить свой провайдер: укажите название, адрес API, имя переменной
ключа, поддерживаемые инструменты и модель в нужном профиле. Нативный запуск
требует совместимости с протоколом Responses и инструментами Codex; одного
совпадения названия API с OpenAI недостаточно. Поддержка инструментов отмечается
по документации провайдера, а не определяется панелью автоматически.

API-ключ сохраняется в системной связке macOS. Другие проекты с тем же адресом
API и именем переменной могут использовать этот ключ. Переменная окружения,
если задана, имеет приоритет. Ключ не записывается в файлы проекта и не возвращается
браузеру. На других ОС используйте переменную окружения. Удаление общего ключа
влияет на все проекты, использующие эту запись связки. Перед удалением панель
показывает провайдера и просит подтвердить действие; отмена сохраняет ключ.

Сохранение обновляет `.orchestra/project.toml` и инструкции исполнителей.
Если другой чат изменил настройки или интеграционные файлы изменены вручную,
сохранение останавливается. Кнопка «Перечитать» загружает текущую конфигурацию.
Для проекта без Orchestra доступно явное подключение; простое открытие проекта
ничего в нём не меняет.

## Связи и точность данных

Новая задача, созданная через `task start` внутри чата Codex, сохраняет
`CODEX_THREAD_ID`. При запуске вне чата можно явно указать `--chat-id UUID`.
Старые задачи без такой записи показываются без связи с чатом. Связи между
задачей и исполнителем читаются из сохранённых событий с `task_id`.

Состояние чата определяется по последнему доступному событию в ограниченном
хвосте журнала. Если событие отсутствует, показывается «Состояние неизвестно».
Записанный статус задачи не подтверждает, что её процесс всё ещё работает.

У завершённой задачи отдельно проверяется актуальность сохранённых проверок.
Если исходники или материалы проверки изменились, история завершения сохраняется,
а карточка сообщает, что текущему коду нужна новая проверка.

Прочерк в счётчиках означает неизвестное значение. Расход руководителя и
произвольных чатов не прибавляется к счётчикам исполнителей. Название модели
в запуске означает запрошенную настройку. Панель не рассчитывает сумму списания.

## Где работают данные

Сервер слушает только локальный адрес компьютера. Он не отправляет данные
во внешние сервисы и не загружает шрифты или библиотеки из интернета. Наблюдение не меняет проекты. Изменения настроек и подключение Orchestra
происходят только по нажатию соответствующей кнопки. Панель проверяет локальный
адрес, источник запроса и токен сеанса. Запуск и отмена задач остаются в Codex.

Повреждённая запись не скрывает исправные данные. Технические предупреждения
сохраняются в ответах локального API; постоянных служебных подписей на экране нет.
Файл задачи хранит последний результат, общие показатели и недавние обновления
в пределах 256 КиБ. Старые записи истории удаляются по мере роста файла;
`history_dropped` показывает их число. Последний результат, номер обновления
и накопленные показатели сохраняются. Большие отчёты стоит хранить отдельно
и указывать ссылкой: слишком большой текущий результат не заменит сохранённое состояние.

История исполнителей включает до 100 последних запусков проекта по времени
изменения их локальных каталогов. Более старые записи остаются на диске.

Чтение файлов, числа проектов, задач и чатов ограничено. Список чатов зависит от доступной локальной схемы
Codex. Удалённые и облачные чаты не выдаются за локально наблюдаемые.

## Оформление и сборка

Панель сохраняет стеклянное оформление из видео: узкая полоса иконок,
полупрозрачное рабочее окно на доступную ширину и высоту. Спокойный фон
помогает читать данные. Раздела выбора оформления нет. На узком экране
карточки и поля перестраиваются; выпадающие меню оформлены вместе с панелью.

Интерфейс написан на React. Как в показанном примере кода, используются
`framer-motion` и `lucide-react`. Все библиотеки включены в локальный `app.js`.
Node.js нужен только для изменения и сборки интерфейса:

```bash
cd frontend
npm ci --ignore-scripts
npm run build
```

Запуск готовой панели требует только Python. Зависимости сборки закреплены
в `package-lock.json`; совместимые версии внутренних модулей Motion указаны
в `overrides`.

Изображение `src/orchestra_kit/web/room.png` создано встроенным imagegen по кадру
видео как отдельная фотография интерьера, без текста и интерфейса. Запрос:
фотореалистичная современная гостиная, диван цвета овсяного льна слева,
круглый стол из ореха, большое растение, светлые шторы, кухня и каменный остров
справа, естественный дневной свет, тёплая нейтральная палитра, формат 16:9.
Фотография хранится локально и не влияет на данные оркестра.
