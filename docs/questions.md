# Короткий вопрос исследователю

Если исполнителю не хватает одного факта, он формулирует узкий вопрос и
передаёт его главному агенту. Главный агент решает, нужен ли исследователь,
назначает ему отдельное задание и сохраняет ответ. Исполнитель не создаёт
других агентов и не расширяет свою задачу.

## Записать вопрос

Главный агент сохраняет `request.json`:

```json
{
  "task_id": "UUID текущей задачи",
  "revision": 0,
  "leaf_id": "UUID исполнителя",
  "question": "Какое поле возвращает существующий разбор ответа?",
  "files": ["src/client.py"],
  "environment": {"response_schema": "items-v1"}
}
```

```bash
./bin/orchestra question ask "<проект>" --input request.json
```

Используйте текущую ревизию из `task show` и сохраните возвращённый
`question_id`. Вопрос привязан к задаче, исполнителю, версии файлов,
конфигурации и указанным условиям окружения. UUID связывают локальные записи;
они не подтверждают личность автора.
Вопрос, ответ и цель задачи ограничены 2 000 символами каждый; вся запись —
6 000 байтами. Превышение отклоняется до сохранения, без обрезки цели.

## Сохранить ответ

После отдельной работы исследователя главный агент записывает `answer.json`:

```json
{
  "answer": "Разбор использует поле items; проверьте обработку отсутствующего поля.",
  "evidence_refs": [],
  "environment": {"response_schema": "items-v1"}
}
```

```bash
./bin/orchestra question answer "<проект>" QUESTION_UUID --input answer.json
./bin/orchestra question read "<проект>" QUESTION_UUID --environment environment.json
```

`environment.json` содержит текущие условия, например
`{"response_schema":"items-v1"}`. Если есть сертификаты проверок относящихся
к вопросу файлов, добавьте их в `evidence_refs`: они должны оставаться актуальными.

Повторная запись того же ответа допустима; другой ответ под тем же ID
отклоняется. При изменении исходников, условий, конфигурации или ревизии задачи
ответ не передаётся исполнителю: `read` возвращает `stale` с ненулевым кодом.
Поставьте новый вопрос по текущим данным.

Команды только сохраняют и проверяют локальные записи. Они не вызывают модель,
не выбирают исследователя и не отправляют ему сообщение автоматически.
Совет остаётся справочными данными; проверки результата и независимое ревью
продолжают действовать. Расход работы исследователя включают в общий расход
задачи. Сами записи находятся в `.orchestra/questions`; исключите их из Git.
Если процесс оборвался и оставил файл блокировки, главный агент сначала
проверяет, что запись больше никто не выполняет, затем удаляет оставшийся lock.
Истечение времени само по себе не разрешает повторную запись.
