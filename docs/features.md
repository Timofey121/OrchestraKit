# Возможности

## Подключение проекта

`setup` устанавливает переносимый пользовательский навык, управляемый глобальный
блок инструкций и определения hooks. `init` создаёт проектную конфигурацию и
сгенерированные роли. `sync` пересобирает управляемые файлы после изменения
`project.toml`, а `doctor` ищет локальные ошибки конфигурации и дрейф.

```bash
./bin/orchestra setup
./bin/orchestra init "<проект>" --name "Название"
./bin/orchestra sync "<проект>"
./bin/orchestra doctor "<проект>"
```

Откройте новый чат Codex после `init` или `sync`, чтобы он прочитал новые
проектные инструкции.

## Роли, профили и маршрутизация

Шаблон содержит роли `explorer`, `worker`, `tester` и `reviewer`. Профили
`cheap`, `balanced`, `strong` и `critical` сопоставляют намерение с моделью и
effort. Команда `route` показывает решение для роли без запуска модели:

```bash
./bin/orchestra route "<проект>" --role worker --complexity complex --risk high --independent
```

При первой ошибке реализации маршрут предлагает ремонт. Повторная ошибка может
поднять профиль, если он настроен. Нехватка контекста предлагает собрать
сведения; ошибка среды и исчерпанный лимит попыток останавливают запуск.
Маршрутизация не меняет модель root chat.

## Ограниченные задания и выполнение

`brief` проверяет шесть обязательных разделов задания. `execute` запускает один
листовой процесс с выбранным профилем и назначенными командами проверки.
`worktree` подготавливает отдельный каталог и проверяет заявленную область
изменений. `cancel` фиксирует запрос на отмену активного запуска.

```bash
./bin/orchestra brief "<проект>" --input brief.json
./bin/orchestra execute "<проект>" --input job.json --dry-run
```

`--dry-run` проверяет маршрут и входные данные, не вызывая Codex. Успех листа
означает, что его финальный ответ и назначенные проверки записаны; root chat
всё равно проверяет diff и принимает интеграцию.

## Состояние, evidence и очередь

`task` сохраняет цель, ревизии, критерии и доказательства. `evidence run`
запускает назначенные проверки и записывает их привязку к исходникам. `handoff`
собирает короткое продолжение, связанное с сохранённой задачей.

`queue` хранит граф работ с зависимостями и fenced leases. Доступны `submit`,
`claim`, `heartbeat`, `settle`, `cancel`, `recover` и `inspect`. Очередь локальна
проекту и не запускает фоновый daemon.

## Наблюдения и панель

`usage` сводит доступные token counters из JSONL-журналов. Команда сохраняет
неизвестные или неполные значения как неизвестные.

```bash
./bin/orchestra usage session.jsonl
./bin/orchestra ui "<проект>" --no-browser
```

Панель по умолчанию слушает `127.0.0.1:8731`, показывает локальные проекты,
доступные чаты Codex, задачи, попытки и evidence. `--no-codex` ограничивает её
явно переданными Orchestra-проектами.

## Hooks и активация

`install-hooks` готовит определения hooks. Их доверие подтверждается человеком
в `/hooks` Codex. `activation` читает публичные tool logs и сообщает, есть ли
наблюдаемое свидетельство чтения навыка. Это наблюдение доставки инструкций,
а не гарантия будущего поведения модели.

## Внешние Responses-провайдеры

Провайдер задаётся в `[providers]`, а профиль ссылается на него. Поддерживается
Responses wire API. Ключ берётся из указанной переменной окружения или, на
macOS, из Keychain. Для запуска доступны только профили, чьи возможности
покрывают требования задачи. Локальная проверка оценивает конфигурацию, формат каталога и наличие ключа.
Доступность модели у провайдера и совместимость реального ответа требуют
отдельной проверки. Модель главного чата выбирается в Codex.

## Сравнение профилей и пределы расхода

`calibrate` сравнивает профили на одинаковом наборе заданий, учитывая все попытки
и критерии качества. Фактические метрики поступают из результатов запусков.
Неполные данные не дают основания объявить профиль более экономичным.

В конфигурации можно ограничить число запусков и порог наблюдаемых токенов
перед повторной попыткой. Это не денежный лимит и не ограничение уже начатого
запроса. Размер заданий, ответов и сохраняемых журналов также ограничен.
Кэширование провайдера и Batch API набор самостоятельно не включает.
