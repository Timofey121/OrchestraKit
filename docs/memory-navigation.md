# Память решений и продолжение работы

Orchestra может сохранить принятое решение и найти его при похожем сбое.
Записи остаются внутри проекта. Поиск выполняется локально и не вызывает модель.
Главный агент сверяет найденное решение с текущей задачей и читает исходники.

## Сохранить решение

Сначала завершите задачу через `task record`: нужны успешные проверки и финальное
ревью с актуальными сертификатами `evidence_ref`, принадлежащими этой задаче.
Запись со словами «всё проверено» без этих артефактов не подходит.

Если сертификаты принадлежат отдельным запускам исполнителя и ревьюера,
главный агент сначала принимает их в задачу:

```bash
./bin/orchestra evidence bind "<проект>" --ref .orchestra/evidence/CHECK.json --kind check --task-id TASK_UUID
./bin/orchestra evidence bind "<проект>" --ref .orchestra/evidence/REVIEW.json --kind review --task-id TASK_UUID
```

Команда создаёт новые ссылки с владельцем-задачей. Она повторно проверяет
исходники, журналы и отчёт ревью, сохраняет исходные сертификаты и не превращает
обычную проверку в ревью. В `task record` укажите новые ссылки. Принятие выполняют
после оценки результата и независимости ревьюера, до завершения задачи.

Создайте `solution.json`:

```json
{
  "task_id": "UUID завершённой задачи",
  "symptom": "KeyError при чтении ответа",
  "scope": "Разбор JSON ответа сервиса",
  "environment": {"python": "3.11", "response_schema": "items-v1"},
  "cause": "Код ожидает поле result, сервис возвращает items",
  "fix": "Читать items и сохранить проверку формата ответа",
  "files": ["src/client.py", "tests/test_client.py"]
}
```

```bash
./bin/orchestra memory store "<проект>" --input solution.json
./bin/orchestra memory search "<проект>" --query "KeyError JSON" --environment environment.json
```

`environment.json` содержит текущие условия, например
`{"python":"3.11","response_schema":"items-v1"}`. Укажите условия, от которых
зависит исправление. Orchestra сравнивает переданные значения; автоматически
определить все зависимости он не может.

Поиск возвращает до трёх подходящих решений. Если исходники, доказательства
или указанные условия изменились, запись исключается из результатов и учитывается
как устаревшая. Одинаковые записи не размножаются. Память ограничена 100 записями.
Известные ключи и пароли из окружения сохранять нельзя. Не помещайте секреты
в симптомы, условия или описание исправления.

Сертификаты подтверждают сохранённые проверки и версию файлов. Смысл причины
и исправления оценивает главный агент. Локальные файлы не удостоверяют личность
автора и не защищают от пользователя, который намеренно переписал всю историю.

## Передать решения следующей попытке

В существующий JSON для `handoff` можно добавить:

```json
{
  "decisions": [{"text": "Сохраняем текущий формат", "reason": "Это требование задачи"}],
  "verified_facts": [{"text": "Проверка формата прошла", "reason": "Проверен текущий код", "evidence_ref": ".orchestra/evidence/UUID.json"}],
  "rejected_approaches": [{"text": "Повторить запрос без изменения разбора", "reason": "Ошибка воспроизводится", "artifact_ref": ".orchestra/checks/attempt.log"}]
}
```

Это дополнительные поля; остальные обязательные поля `handoff` сохраняются.
Проверенные факты требуют актуального сертификата проверки. Для отвергнутого
подхода нужен доступный артефакт попытки. Наличие файла само по себе не доказывает
причину отказа: её проверяет агент. При новых данных подход можно пересмотреть.
Артефакты попыток берутся из `.orchestra/checks` или `.orchestra/executions`.
Цель, ограничения и незакрытые ошибки продолжают передаваться целиком.

## Найти код

Необязательная карта хранит пути и расположение Python-функций и классов:

```bash
./bin/orchestra navigate build "<проект>" --path src/client.py --path tests/test_client.py
./bin/orchestra navigate search "<проект>" --query "parse_response"
```

Каждая сборка задаёт полный набор индексируемых файлов. Неизменившиеся файлы
используются повторно. Изменённые или удалённые файлы исключаются при поиске;
обновите карту командой `build`. Для других языков доступна навигация по пути.
Карта не выводит связи между тестами и функциями и не заменяет чтение кода.
Для простого поиска можно продолжать пользоваться `rg`.
Сборка выводит короткую сводку; `--json` возвращает весь индекс. Поиск памяти
и карты возвращает компактный JSON, чтобы форматирование не расходовало
выделенный объём ответа.

Память и карта находятся в `.orchestra/memory` и `.orchestra/navigation`.
Исключите их из Git подключённого проекта. Это локальные данные работы.
Команды не добавляют память в каждый запрос исполнителя автоматически:
главный агент выбирает полезные записи и включает нужные сведения в ограниченное
задание. Экономию оценивайте через `compare-workflows` на своих задачах.
